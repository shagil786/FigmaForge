Three-file module with a clear separation of concerns: `test_framework.ts` implements a tiny in-process test harness exporting `describe`, `it`, and assertion helpers (`assert`, `assertEqual`, `assertThrows`, `assertRejects`, etc.) plus result aggregation via `SuiteResult`/`TestResult` interfaces. `test_all.ts` is the single test registry — it imports production code from `../src/core/*` (types, events, checkpoint, artifacts, tools, state, budget, retry, security, pipeline, evaluation, providers, screenshot comparator) and groups assertions into numbered suites under one exported `runAllTests()` function returning an array of `SuiteResult`. `run_all.ts` is the CLI entry point: it calls `runAllTests()`, prints results via `printResults`, and exits with code 1 if any suite has failures. Dependency direction is strictly inward: `run_all.ts` → `test_all.ts` → `test_framework.ts` + `../src/core/*`; tests never import each other.
