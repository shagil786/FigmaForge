The package is organized as a thin CLI entry (`src/cli/main.ts`) that parses argv and dispatches to command handlers; each handler constructs a shared `RuntimeConfig` from flags and instantiates the same set of core services — `EventLog`, `CheckpointManager`, `ArtifactStore`, `ToolRegistry`, `BudgetTracker`, and `PipelineCoordinator` — all imported from `src/core/`. The `core_runtime` child provides the deterministic stage pipeline and its cross-cutting concerns (budgets, retry, security, checkpointing), while the `evaluation_harness` child supplies golden fixtures consumed by tests that drive the same pipeline. The `tests` child runs against the compiled output via `node --experimental-vm-modules dist/tests/run_all.js`. Cross-child cohesion comes from the shared `src/core/types.ts` defaults (`DEFAULT_CONFIG`, `DEFAULT_BUDGETS`, `DEFAULT_RETRY`, `PIPELINE_STAGES`) and the convention that every command resolves outputs under `<output-dir>/<run-id>/artifacts` and `<output-dir>/<run-id>/renders`, so inspect/replay/render/compare/repair operate on artifacts produced by run.
