The workspace is split into two sibling packages that share the same domain model: `plugin/figmaforge/` (Python) implements the Claude Code plugin — detector, router, lifecycle state machine, agents, skills, hooks, and the Figma → Design IR pipeline — while `runtime/` (Node/TypeScript) exposes the same pipeline as a `figmaforge` CLI with run/inspect/replay/render/compare/repair commands. Both children consume common artifacts under `docs/` (architecture, design-IR, resolution, layout, repair-loop) and reference the same schema/fixtures contracts (`schemas/`, `fixtures/figma/`, `evaluation/fixtures/golden/`) so the plugin's IR output is directly consumable by the runtime's pipeline. The root-level `tsconfig.json` scopes TypeScript compilation to `runtime/src/**/*` and `runtime/tests/**/*`, keeping the Python plugin isolated; the top-level `package.json` only declares dev tooling for the repo, while each child manages its own dependencies. Cross-child wiring happens at the user boundary: users invoke either `claude --plugin-dir ./plugin/figmaforge` or the `figmaforge` CLI, both of which drive the same IR → layout plan → code generation stages documented in `docs/runtime-architecture.md` and `docs/architecture.md`.
