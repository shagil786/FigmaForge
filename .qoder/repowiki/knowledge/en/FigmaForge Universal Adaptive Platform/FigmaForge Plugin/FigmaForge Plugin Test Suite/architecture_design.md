Tests are organized as one `test_<feature>.py` file per subsystem under `plugin/figmaforge/tests/`, each importing the corresponding `core.*` module via `sys.path.insert(0, plugin_root)` so tests can be executed directly with `python3`. Snapshot-style tests (`test_ir_snapshot.py`, `test_layout_snapshot.py`, `test_resolution_snapshot.py`, `test_generator_snapshot.py`) build deterministic payloads from `core.figma_fixtures.FixtureLoader` data under `fixtures/figma/`, serialize them via `*_to_json` helpers, and compare byte-for-byte against checked-in JSON files in `tests/snapshots/` (e.g. `file.json`, `layout-plan.json`, `resolution-report.json`, `generator/desktop-gen.json`). Non-snapshot unit tests cover individual components such as asset handling, components, detector, diff engine, router, state machine, tokens, and repair loop. An integration test (`test_integration.py`) exercises the end-to-end detector/catalog/router path by adding `core` to `sys.path` at runtime.
