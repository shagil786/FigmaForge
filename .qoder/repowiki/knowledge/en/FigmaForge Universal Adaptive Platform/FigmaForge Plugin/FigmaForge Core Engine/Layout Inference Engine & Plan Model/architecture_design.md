Three-layer pipeline inside the module: (1) `constraint_model.py` defines `ConstraintModel` and pure `BoxSolver` arithmetic that extract axis facts (`AxisFacts`) from an `IRNode`, detect contradictions/underdetermined/unsupported issues, and provide clamping/content-box math; (2) `layout_engine.py`'s `LayoutEngine` walks the IR recursively via `_build`, computes provisional content boxes, resolves each axis through `_resolve_axis` (percent → fill → hug → fixed), lays out children in flow/grid/absolute modes, anchors absolute nodes with `_anchor_box`, and accumulates page-absolute offsets in `_finalize`; text measurement is delegated to a pluggable `TextMeasurer` heuristic. (3) `layout_analyzer.py`'s `LayoutAnalyzer` orchestrates the engine run at multiple viewport widths, runs `BreakpointModel` (in `breakpoint_model.py`) to diff node signatures across breakpoints and attach `BreakpointChange`s, then aggregates counts, confidence scores (penalized by assumptions in `_ASSUMPTION_PENALTY`), diagnostics, and constraint reports into a single `LayoutPlan`. All shared value types — `Box`, `SizingSpec`, `SpacingSpec`, `AlignmentSpec`, `Anchoring`, `OverflowSpec`, `TextModel`, `LayoutNodePlan`, `LayoutPlan`, `BreakpointPlan`, `Diagnostic`, `ConstraintReport` — live in `layout_types.py` as dataclasses with `to_dict()` / `_compact` serialization, forming the stable contract between this module and downstream generators.
