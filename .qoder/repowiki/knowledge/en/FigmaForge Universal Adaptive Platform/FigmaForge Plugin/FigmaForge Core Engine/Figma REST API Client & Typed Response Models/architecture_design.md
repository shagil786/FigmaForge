Three cooperating modules form the ingestion boundary against the Figma API. `figma_types.py` defines frozen `dataclass` value objects (`Color`, `Paint`, `Effect`, `AutoLayout`, `TextStyle`, `Node`, `FigmaFile`, `FigmaNodeResponse`, `ImageSet`) that mirror the Figma v1 response shapes; each exposes a static `from_dict` constructor that coerces unknown/missing keys to safe defaults so normalization is deterministic and testable without network access. `figma_errors.py` declares a `FigmaError` base class with subclasses (`FigmaAuthError`, `FigmaNotFoundError`, `FigmaRateLimitError`, `FigmaServerError`, `FigmaTimeoutError`, `FigmaNetworkError`, `FigmaValidationError`, `FigmaResponseError`) used uniformly by callers to branch on failure type rather than parsing messages. `figma_client.py` implements `FigmaClient`, a thin HTTP wrapper around `urllib.request` (no external deps) that reads the token from the `FIGMA_TOKEN` env var, performs JSON requests with exponential backoff over a configurable `_RETRYABLE_STATUS` set, honors `Retry-After` headers, enforces a client-side rate-limit gap via `_throttle`, and maps HTTP status codes into the typed exceptions from `figma_errors`. The transport layer is injected through an optional `transport` callable argument so unit tests can drive retries and error mapping without a live network or token. Dependency direction is one-way: `figma_client` imports both `figma_errors` and `figma_types`; types and errors have no internal dependencies.
