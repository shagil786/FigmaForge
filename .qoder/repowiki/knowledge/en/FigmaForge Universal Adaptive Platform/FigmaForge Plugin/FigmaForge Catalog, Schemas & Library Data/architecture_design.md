Three sibling data directories with no executable code:
- `catalog/` — `roles.json` is a domain-grouped catalog (`discovery`, `experience`, `architecture`, `application`, `data`, `quality`, `delivery`, `governance`, `growth`) where each role entry declares `phases`, `triggers`, `deliverables`, `repository_signals`, `risk`, `capability_refs`, and a `fallback_pack`; an empty `domains/` directory is reserved for future domain metadata.
- `schemas/` — JSON Schema Draft-07 files that define the contract between Figma file responses and FigmaForge's internal representations: `design-ir.schema.json` (the normalized design IR with node/component/style/variable graphs), plus schemas for pipeline artifacts (`detection`, `layout-plan`, `resolution-report`, `router`, `task-state`). Each schema uses `$schema`, `$id`, `definitions`, and an inline `example` to serve as both validation spec and documentation.
- `library/` — `components.json` and `tokens.json` are project-specific manifests declaring existing UI components and design tokens; their `description` fields document that the resolution layer prefers these over generating new ones, making them the source of truth for token/component reuse.
Dependency direction is one-way: runtime code in other modules reads these JSON files at startup or on demand; this module has no imports from elsewhere.
