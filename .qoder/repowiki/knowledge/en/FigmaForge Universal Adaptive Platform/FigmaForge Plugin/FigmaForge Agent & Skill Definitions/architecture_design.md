This module is a pure content layer — each file under `agents/` and `skills/` is a self-contained Markdown document with a YAML frontmatter block declaring `role`, `type`, `scope`, `id`, and optional `description`. Agents are declared as `subagent` types (`figmaforge:context-scout`, `figmaforge:fresh-verifier`, `figmaforge:lifecycle-planner`) and skills as `skill` types (`figmaforge:route`, `figmaforge:doctor`, `figmaforge:lifecycle`, `figmaforge:lsp-template`, `figmaforge:mcp-template`, `figmaforge:demo`). The `route` skill acts as the entry point: it inspects the repository via `detector.py`, consults `catalog/roles.json`, scores roles against triggers/lifecycle phases, and selects an execution mode (`direct | isolated_scout | isolated_planner | fresh_verifier`) along with approval gates. Skills and agents declare explicit trigger keywords that the router matches to select them, and they constrain themselves to read-only or inert operations (no writes, no external API calls, no credential injection). State persistence for task runs is delegated to `.figmaforge/runs/<run-id>/state.json` and `events.jsonl` by the lifecycle skill, while LSP/MCP template skills render only inert templates without touching user config files.
