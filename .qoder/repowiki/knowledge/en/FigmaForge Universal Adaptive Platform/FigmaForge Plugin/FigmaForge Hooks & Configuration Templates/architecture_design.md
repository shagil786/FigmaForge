Two sibling subdirectories serve distinct, data-driven configuration roles consumed by the FigmaForge plugin at runtime:
- `hooks/hooks.json` declares a `hooks` map keyed by event names (`SessionStart`, `PreToolUse`, `PostToolUse`). Each entry is an array of hook descriptors with `command`, `description`, and nested `hooks`, pointing to Python scripts under `core/hooks/` that are executed as subprocesses during the corresponding lifecycle phase.
- `templates/lsp/` holds LSP server configuration templates: `official-plugins.json` is a declarative matrix mapping programming languages to Claude Code MCP plugin install commands and required binaries, while `custom-server.example.json` is a JSON Schema–annotated template for user-defined `.lsp.json` entries.
- `templates/mcp/` ships inert example MCP server configs (`stdio.example.json`, `http-oauth.example.json`) plus a `README.md` documenting safe usage — templates use placeholder URLs (`example.invalid`) and environment-variable placeholders so they cannot be executed accidentally; consumption goes through `figmaforge mcp render` which writes only to stdout.
Dependency direction is one-way: these static JSON assets are read by higher-level FigmaForge code to bootstrap tooling (LSP/MCP) and to invoke hooks; no executable logic lives in this module.
