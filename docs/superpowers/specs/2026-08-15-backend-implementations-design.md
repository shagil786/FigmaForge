# Backend Implementations — React+Tailwind / Vue / Svelte / SwiftUI / Flutter (Part 14) — Design Spec

## Context

- `plugin/figmaforge/backends/` (Part 10) defines the backend protocol: `protocol.py` (Feature vocabulary, `FidelityLoss`, `GeneratedFile`/`GeneratedOutput`, `BackendCapabilities`, `BackendAdapter` ABC with `generate()` + a default `preflight()` that walks IR nodes and reports losses for unsupported features) and `registry.py` (register/lookup/find/preflight, `discover_builtins`, module-level `get_registry()`).
- Six backends are registered: **html_css (fully implemented — the reference, 517 lines)** and five stubs: `react_tailwind`, `vue`, `svelte`, `swiftui`, `flutter` (140–190 lines each).
- The html_css reference lowers `LayoutPlan` → per-screen `VNode` trees (`_VNodeBuilder`, semantic tag map) → `VStyle` CSS properties (`_CSSStyleGenerator` over `LayoutNodePlan` fields: box/sizing/spacing/alignment/direction/text/overflow/breakpoints) → `_HtmlEmitter` (HTML + CSS rules) + `_wrap_html_document`, with escaping helpers and `_camel_to_kebab`. `LayoutNodePlan` (core/layout_types.py:413) carries `box`, `sizing`, `spacing`, `alignment`, `text`, `overflow`, `breakpoints`, `children`.
- **The five stubs do NOT generate real code**: each `generate()` emits a placeholder component containing `TODO: Generate from LayoutPlan for node …` (verified: react_tailwind emits a static TSX div, vue/svelte emit empty templates, swiftui/flutter emit a static Text). Capabilities ARE declared honestly (supported/partial/unsupported sets per backend).
- `tests/test_backends.py` `TestStubBackends` asserts ONLY `name`/`display_name`/`capabilities`/file extensions — nothing about generated content, so replacing placeholders with real generators will not break it. html_css has dedicated tests (empty layout, capabilities) and is covered by generator/snapshot tests elsewhere.
- The TS runtime's `--target` (`runtime/src/core/types.ts` `PRESET_TARGETS`) is the runtime's OWN `CodegenTarget` concept (framework+styling pairs for runtime evaluation) — there is NO existing hook from the TS runtime into the Python backends, and adding one is out of scope.
- Repo rules that constrain this work: stdlib-only (no new Python deps), deterministic output (no randomness), golden/snapshot test convention (`REWRITE_SNAPSHOTS=1`), no binary fixtures, `python3 -m unittest` (no pytest), and `claude plugin validate --strict` must pass.

## Decisions (user-approved scope)

- **"Implement the five stubs" = real LayoutPlan → target-code lowering** for all five backends, replacing the placeholder generators, while keeping the protocol contract, capability declarations, and the reference html_css backend unchanged in behavior.
- **Coverage target: the common IR surface** exercised by WEB_COMMON_FEATURES and the golden fixtures — flex layout (direction/gap/justify/align), fixed/fill/hug/percent sizing, padding, solid fills, borders, corner radius, opacity, typography (family/weight/size/line-height/letter-spacing/align), text, design tokens, per-screen components. Anything beyond (gradients/images, interactions, breakpoints on native, component variants, absolute positioning where a backend declares it unsupported) is reported as an explicit `FidelityLoss` with a named fallback — never silently dropped.
- **Shared web machinery** for the three web backends + html_css: extract `VNode`/`VStyle`/`_CSSStyleGenerator`/`_VNodeBuilder`/semantic-tag map/escaping into a shared `backends/web_common.py`. html_css imports from it (a transparent refactor — its tests and snapshots are the safety net and must stay green). Vue/Svelte reuse the CSS style output directly (scoped CSS); React+Tailwind converts it via a deterministic CSS→Tailwind-class mapper.
- **Native backends are self-contained**: SwiftUI and Flutter each get their own `LayoutNodePlan` → view/widget lowering + emitter (SwiftUI modifier chains / Flutter widget tree). No web machinery.
- **Python-only.** No TS runtime wiring (none exists); no compilers invoked (swiftc/dart/tsc are not guaranteed installed and runtime-deps rule forbids them) — verification is structural (file sets, node coverage, no placeholders, syntactic markers) + golden snapshots + fidelity-loss assertions.
- **Deterministic golden tests** per backend for one representative screen, following the repo snapshot convention.

## Design

1. **Shared web machinery** — new `backends/web_common.py` holding (moved verbatim from html_css, made public, no behavior change): `VStyle`, `VNode`, `CssStyleGenerator`, `VNodeBuilder`, `_SEMANTIC_TAG_BY_NAME` + tag lookup, `camel_to_kebab`, `escape_html`, `escape_attr`. `html_css/__init__.py` re-imports from it. The three web backends import the same module — ONE style-mapping implementation, five entry points (html_css + three web stubs), mirroring the repo's "one real implementation" principle from Parts 12–13.
2. **react_tailwind** — real TSX generator: per screen, build the VNode tree (shared builder), convert each node's `VStyle.base` via a deterministic CSS→Tailwind mapper into `className` strings, and emit a functional component (`export function {Name}({...})`). Mapper strategy: **arbitrary-value classes for exactness** (`bg-[#f5f5f5]`, `w-[400px]`, `rounded-[8px]`, `pt-[24px]`, `text-[14px]`) with standard classes only where exact (`flex`, `flex-col`, `items-center`, `justify-between`, `gap-4`→ always `gap-[Npx]`). Breakpoints → Tailwind responsive prefixes from `VStyle.breakpoints` (prefix value → `md:`/`lg:` by the breakpoint width) where the backend declares `MEDIA_QUERIES` partial. Components: each screen = one `.tsx`; `tailwind.config.figmaforge.js` now extracts REAL design tokens (colors/spacing/fontFamily) from `resolution` (or IR tokens) instead of empty TODO blocks. Absolute positioning (declared unsupported): `preflight` loss + fallback `position: relative` on parent via arbitrary classes, marked inline.
3. **vue** — real `.vue` SFC generator: `<template>` = div tree with scoped class names (`n-{node_id}`), `<script setup>` = `defineProps` + the component, `<style scoped>` = the CSS rules produced by the shared `CssStyleGenerator` (identical selector rules as html_css but scoped). Breakpoints → scoped `@media` rules.
4. **svelte** — real `.svelte` component generator: `<script>` (props), markup with `class="n-{node_id}"`, `<style>` (scoped by Svelte semantics) with the shared CSS rules. Breakpoints → `@media` rules.
5. **swiftui** — real `.swift` generator: `struct {Name}View: View` with `#Preview`; recursive lowering: flex containers → `VStack(spacing:)`/`HStack(spacing:)` (alignment mapped from justify/align), leaves → `Text(_:)` or `Color(...)` rect; modifier chain per node: `.frame(width:height:alignment:)`, `.padding(.leading/.trailing/.top/.bottom, N)` (single `.padding(N)` when uniform), `.background(Color(red:green:blue:))`, `.foregroundColor(...)`, `.font(.system(size:weight:))`, `.lineSpacing`, `.kerning`, `.multilineTextAlignment`, `.cornerRadius(N)`, `.opacity(N)`, `.border(...)` for 1px borders, `.shadow(...)` where supported. Hex → `Color(red: 0.20, green: 0.40, blue: 0.80)` (deterministic 0–1 doubles, 2-decimal rounding). Viewport default 390 (already the stub default). Unsupported (grid, absolute positioning where declared, gradient/image fills, breakpoints): `preflight` losses; the emitter degrades (e.g. gradient fill → solid fallback color; absolute → in-flow frame) with an inline `// fidelity: <feature> approximated` marker.
6. **flutter** — real `.dart` generator: `class {Name}Screen extends StatelessWidget` with `Scaffold`; recursive lowering: row/column → `Row`/`Column` (`mainAxisAlignment`, `crossAxisAlignment`, `SizedBox(width: gap)` separators), leaves → `Container` (`BoxDecoration(color: Color(0xFF......), borderRadius: BorderRadius.circular(N), border: Border.all(...), boxShadow: [...])`, `padding: EdgeInsets.only(...)`), `SizedBox(width:height:)` for fixed sizing, `Text` with `TextStyle(fontSize:, fontWeight:, color:, height:, letterSpacing:)`, `Align` for alignment. Viewport 390. Unsupported features → losses + degrade with `// fidelity: <feature> approximated` marker.
7. **Fidelity honesty rule** (applies to all five): the generator's fallback for an unsupported feature must be either (a) named in the `FidelityLoss.fallback_applied` from `preflight`, or (b) marked inline in the generated file with a `// fidelity:` / `{/* fidelity: */}` / `<!-- fidelity: -->` comment — never silent. The `preflight()` output remains the single loss source (no second loss pass in the generators).
8. **Testing** — deterministic programmatic fixtures (a small multi-node screen: container + text + colored button, plus one fixture exercising an unsupported feature per backend), built via `core.ir_types`/`core.layout_types` per the repo's `_make_plan` convention. Assertions per backend: correct file set + `node_ids` coverage; no placeholder markers (`TODO: Generate from LayoutPlan` absent); structural markers present (TSX `export function`/`className`, SFC `<template>`/`<style scoped>`, svelte `<script>`, swift `struct …: View`/`#Preview`, dart `class … extends StatelessWidget`); token config contains real tokens (react_tailwind); fidelity losses emitted for unsupported fixtures; deterministic (generate twice → identical bytes). One **golden snapshot** per backend under `tests/snapshots/` (repo convention, `REWRITE_SNAPSHOTS=1` to regenerate). html_css behavior unchanged (existing tests green).
9. **Docs** — `docs/DEVELOPMENT_LOG.md` Part 14 entry (final counts); `README.md` (Part 10 checklist line "5 stubs" → implemented; status header Parts 1–14; Next Steps drop the stub item); `CLAUDE.md` (module line + test counts); `docs/architecture.md` implementation-status paragraph; backend docstrings updated (they currently claim "placeholder"/"stub").

## Risk mitigations

1. **html_css refactor risk** — the extraction is verbatim moves; html_css tests + generator snapshots are the safety net; the refactor lands as its own task with a full-suite run before any stub changes.
2. **Tailwind mapping incompleteness** — arbitrary-value classes make every CSS property representable; the mapper has a documented fallback: any unmapped property emits a loss with `fallback_applied` rather than being dropped.
3. **SwiftUI/Flutter syntax without a compiler** — conservative, well-known API surface only; structural tests pin the emitted shape; no exotic modifiers; every string literal escaped; deterministic formatting.
4. **Scope creep** — the coverage target is the common IR surface; gradients/images/interactions/breakpoints-on-native are explicitly non-goals with losses; the plan's per-task acceptance criteria enumerate exactly what each backend must emit.
5. **Honest fidelity** — unsupported features are never silently approximated: preflight loss + named/inline fallback marker (rule 7).

## Non-goals

- TS runtime integration (no hook exists; `--target` is a separate concept).
- Invoking real compilers (swiftc/dart/tsc) or building/rendering the generated apps.
- Full parity with html_css for every IR feature (gradients/images/interactions/component variants/breakpoints on native backends — losses instead).
- New Python dependencies; non-deterministic output; any change to html_css generated output.
- Python `main()`-level CLI changes; registry/protocol changes.

## Risks

- **Refactor regressions** in html_css → verbatim extraction + existing-test safety net + dedicated task.
- **Mapper holes** in Tailwind/SwiftUI/Flutter lowering → every fallback is explicit (loss or inline marker); tests cover the fixture surface; remaining holes surface as losses, not silent approximations.
- **Golden snapshot churn** on regeneration → snapshots regenerate deterministically; only the new backend snapshots are added.
- **Unsupported-feature fixture realism** → fixtures exercise real IR nodes (gradient fill, absolute position, grid) so preflight and degradation paths are actually tested per backend.
